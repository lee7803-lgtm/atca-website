# ITCA 官网 V2.0 实施计划

## 分支策略

V2.0 从当前稳定分支创建独立开发分支：

- 基准分支：`feature/itca-v1-3-operations-content-flow`
- V2.0 开发分支：`feature/itca-v2-navigation-user-auth-rbac`
- 本轮提交：`docs: define ITCA V2 upgrade scope`

实施规则：

- 本轮只提交文档和参考原型。
- 不自动 push。
- 不自动发布 production。
- 后续功能开发应按页面、用户系统、RBAC、数据中心等模块拆分小提交。
- 涉及数据库结构时先提交 SQL 草案和迁移说明，不直接执行。

## 页面开发清单

V2.0 页面开发按导航升级版信息架构分批实施：

- 首页：整合协会定位、V1.3 业务入口、发展中心、会员认证、证书查验、发展合作、数据中心入口。
- 介绍页面：协会宗旨、使命、定位、国际合作、服务对象。
- 规章制度页面：章程、会员管理、认证与建档、隐私、核验、合作规则。
- 道教信仰页面：信仰文化、宫观文化、修行生活、当代表达。
- 教理教义页面：经典导读、伦理修身、生命修炼、术语解释。
- 文化交流页面：国际交流、文化研究、课程研修、机构合作、活动记录。
- 发展中心总览：六大发展中心入口、专委会、项目合作、活动发布。
- 养生与修炼发展中心。
- 文创产业发展中心。
- 教育培训发展中心。
- 国际与交流发展中心。
- 易学与东方认知发展中心。
- 道医中医研究发展中心。
- 会员认证页面。
- 证书查验页面。
- 发展合作页面。
- 数据中心页面。

页面开发必须复用 V1.3 现有视觉和组件基础，避免先做大规模视觉重构。

## 用户系统开发清单

用户系统为 V2.0 后续目标，本轮不开发业务代码。

后续开发清单：

- 注册、登录、退出。
- 账号资料管理。
- 邮箱或手机号绑定。
- 用户身份状态。
- 会员申请记录关联。
- 认证申请记录关联。
- 支付记录关联。
- 证书记录关联。
- 机构账号和联系人管理。
- 用户通知和站内消息。
- 用户端申请进度和历史记录。
- 用户隐私和资料授权说明。

用户系统必须兼容 V1.3 现有匿名或表单式申请查询能力，不能破坏已有申请、支付、证书、核验流程。

## 后台 RBAC 权限开发清单

后台 RBAC 为 V2.0 后续目标，本轮不开发业务代码。

建议角色：

- 超级管理员。
- 业务审核员。
- 财务管理员。
- 证书管理员。
- 会员管理员。
- 内容管理员。
- 数据中心管理员。
- 只读审计员。

建议权限清单：

- 申请查看。
- 申请审核。
- 材料补正。
- 联系方式修正。
- 记录处置。
- 支付查看。
- 支付状态管理。
- 收据管理。
- 证书签发。
- 证书撤销或暂停。
- 证书公开核验字段管理。
- 会员管理。
- 后台基础资料管理。
- 通知发送。
- 数据中心资料审核。
- 内容发布。
- 审计日志查看。

RBAC 必须保持可审计，关键操作应写入审计日志或保留操作记录。

## SQL 草案策略

V2.0 后续如需要用户系统、权限、角色、数据中心或公开展示字段相关数据库结构，只能新增 SQL 草案文件。

要求：

- SQL 文件命名应明确标注 V2.0 和草案属性。
- SQL 草案必须包含用途、影响范围、回滚思路和执行前置条件。
- 不在本地自动执行 SQL。
- 不连接或修改生产数据库。
- 不把 SQL 草案混入业务代码提交。
- 执行 SQL 必须由人工确认并在独立任务中处理。

本轮明确不新增 SQL。

## V1.3 兼容边界

V2.0 必须保留 V1.3 业务闭环：

- 申请提交。
- 后台审核。
- 材料补正。
- 支付和支付记录。
- 证书生成或证书资料管理。
- 公开核验。
- 通知发送。
- 后台基础资料管理。
- 审计日志。
- 记录处置。

兼容要求：

- 不改变现有申请状态语义。
- 不改变现有支付状态语义。
- 不扩大公开核验字段。
- 不破坏现有后台路由。
- 不删除或覆盖现有 Supabase 草案。
- 不改变现有 API 合约，除非后续任务明确包含兼容方案和测试。

## 视觉延续 V1.3 的执行要求

V2.0 视觉执行原则：

- 延续 V1.3 的品牌识别、页面节奏、按钮、卡片、标题、页眉、页脚和内容密度。
- 优先复用现有组件。
- 不做视觉系统重构。
- 不照搬 HTML 原型深色样式。
- 不以 HTML 原型中的颜色、背景、圆角、阴影作为生产视觉标准。
- 新增页面应先套用现有页面模板，再根据内容复杂度做小幅扩展。

页面上线前应检查移动端和桌面端可读性，避免文本溢出、导航遮挡和内容层级混乱。

## HTML 原型的使用边界

参考文件：

`docs/reference/ITCA官网导航升级版_会员认证配色版.html`

使用范围：

- 提取 V2.0 导航结构。
- 提取栏目结构。
- 提取页面内容方向。
- 提取发展中心体系。
- 提取会员认证、证书查验、发展合作、数据中心结构。

禁止范围：

- 不作为最终生产代码。
- 不直接复制视觉样式。
- 不直接复制外部图片依赖。
- 不直接复制脚本交互。
- 不作为组件实现标准。
- 不绕过 V1.3 现有组件和视觉规则。

## 不执行 SQL / 不改生产数据库要求

本轮和后续默认规则：

- 不自动执行 SQL。
- 不直接修改生产数据库。
- 不连接生产数据库做结构变更。
- 不运行迁移命令修改生产环境。
- 不把 SQL 执行结果作为默认交付动作。

如后续确需数据库变更，应先提交 SQL 草案、影响分析和人工执行说明。

## 验收命令

本轮完成后执行：

```bash
git diff --check
git status --short
git add .
git commit -m "docs: define ITCA V2 upgrade scope"
git status --short
git branch --show-current
git rev-parse --short HEAD
```

不得执行：

```bash
npm run dev
npm run build
supabase db push
supabase migration up
git push
```

除非后续任务明确要求并经人工确认。
