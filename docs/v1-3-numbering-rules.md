# V1.3 Numbering Rules

## 1. 编号体系总览

V1.3 后续阶段采用“申请阶段编号”和“正式登记编号”分离的编号体系：

| 编号类型 | 格式 | 使用阶段 | 对外属性 |
| --- | --- | --- | --- |
| 道士认证申请编号 | `ARID-ITCA-TAO-YYYY-000001` | 申请提交、进度查询、补充资料、后台审核 | 申请人本人查询使用 |
| 个人会员申请编号 | `ARID-ITCA-M-YYYY-000001` | 申请提交、进度查询、补充资料、后台审核 | 申请人本人查询使用 |
| 机构会员申请编号 | `ARID-ITCA-ORG-YYYY-000001` | 申请提交、进度查询、补充资料、后台审核 | 申请人本人查询使用 |
| 道士资格认证证书编号 | `ITCA-TAO-YYYY-000001` | 证书生成后 | 公众证书核验使用 |
| 个人会员编号 | `ITCA-M-YYYY-000001` | 会员审核通过后 | 公众会员核验使用 |
| 机构会员编号 | `ITCA-ORG-YYYY-000001` | 机构会员审核通过后 | 公众会员核验使用 |
| 支付订单编号 | `PAY-ITCA-YYYY-000001` | 支付订单创建后 | 申请人支付与内部对账使用 |
| 通知记录编号 | `NTC-ITCA-YYYY-000001` | 通知记录创建后 | 内部管理使用 |

`YYYY` 使用编号生成时所在年份。`000001` 为同一编号类型、同一年内的六位递增序号，后续应由数据库序列表或原子函数生成。

## 2. ARID 定义

ARID = Application Reference ID。

ARID 只代表“申请引用编号”，不代表正式会员资格、正式证书或付款完成状态。申请人提交申请后即可获得 ARID，并使用 ARID 与登记联系方式查询申请进度、补充资料、查看审核反馈。

## 3. 申请编号规则

道士认证申请编号：

```text
ARID-ITCA-TAO-YYYY-000001
```

个人会员申请编号：

```text
ARID-ITCA-M-YYYY-000001
```

机构会员申请编号：

```text
ARID-ITCA-ORG-YYYY-000001
```

申请编号应写入现有申请表的申请编号字段，短期可继续使用 `application_no` 承载，但显示文案必须明确它是申请编号，不是正式证书编号或正式会员编号。

## 4. 正式证书编号规则

道士资格认证证书编号：

```text
ITCA-TAO-YYYY-000001
```

证书编号只在证书记录生成后存在，应写入 `certificates.certificate_no`。公众证书核验使用证书编号与持证人姓名，不使用申请编号。

## 5. 正式会员编号规则

个人会员编号：

```text
ITCA-M-YYYY-000001
```

机构会员编号：

```text
ITCA-ORG-YYYY-000001
```

会员编号只在会员申请审核通过并正式登记后生成。第 6 阶段建议先写入 `applications.member_no`，暂不新增复杂 `members` 独立表。

## 6. 支付与通知编号规则

支付订单编号：

```text
PAY-ITCA-YYYY-000001
```

通知记录编号：

```text
NTC-ITCA-YYYY-000001
```

V1.3 第 5 阶段只正式化规则，不实现支付或通知模块。后续落地时，支付订单编号应绑定付款订单，通知记录编号应绑定通知发送或发送计划记录。

## 7. 编号关系

- 一条申请必须有一个申请编号 ARID。
- 会员申请审核通过后，可以产生一个正式会员编号。
- 道士认证申请审核通过并生成证书后，可以产生一个正式证书编号。
- 申请编号不应在正式阶段继续伪装成会员编号或证书编号。
- 证书编号与会员编号属于不同业务域，不互相替代。
- 支付订单编号、通知记录编号与申请编号可通过业务外键关联，但不应复用同一个编号。

## 8. 展示与查询原则

| 场景 | 应显示 / 查询编号 |
| --- | --- |
| 申请提交成功页 | 申请编号 ARID |
| 申请人进度查询 `/application/query` | 申请编号 ARID + 登记联系方式 |
| 申请人补充资料 | 申请编号 ARID + 登记联系方式 |
| 后台申请列表 / 详情 | 申请编号 ARID，必要时显示正式会员编号或证书编号 |
| 后台审核通知文案 | 申请阶段用 ARID；证书生成后可同时提示证书编号 |
| 公众证书查询 `/certificate-query` | 证书编号 + 持证人姓名 |
| 证书详情 `/certificates/[certificateNo]` | 证书编号 + vt 短期核验凭证 |
| 公众会员查询 `/member-query` | 正式会员编号 + 姓名 / 机构名称 |
| 审计日志 | `resource_no` 优先记录当前操作对象编号；申请审核记录申请编号，后续正式会员操作记录会员编号 |

## 9. 公开与内部边界

可公开查询：

- `ITCA-TAO-YYYY-000001` 证书编号，需配合持证人姓名或短期核验凭证。
- `ITCA-M-YYYY-000001` 个人会员编号，需配合姓名。
- `ITCA-ORG-YYYY-000001` 机构会员编号，需配合机构名称。

只用于申请人查询或内部管理：

- `ARID-ITCA-TAO-YYYY-000001`
- `ARID-ITCA-M-YYYY-000001`
- `ARID-ITCA-ORG-YYYY-000001`
- `PAY-ITCA-YYYY-000001`
- `NTC-ITCA-YYYY-000001`

## 10. 新旧编号兼容原则

- 历史 `application_no` 不做覆盖式改写。
- 旧申请编号继续可用于申请进度查询。
- 当前被当作会员编号使用的旧 `application_no`，在新增 `member_no` 后继续作为兼容查询键。
- 新申请逐步使用 ARID 格式。
- 新会员审核通过后生成 `member_no`，公众会员查询优先查 `member_no`，查不到再兼容旧 `application_no` / `legacy_member_no`。
- `certificates.certificate_no` 已经是独立证书编号，暂不重构。
- 历史数据迁移应分批、可回滚，并在迁移前导出编号映射。
