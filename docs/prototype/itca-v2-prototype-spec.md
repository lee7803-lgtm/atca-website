# ITCA 官网 V2.0 原型设计图与交互说明

版本：V2.0 Prototype Spec

日期：2026-06-16

适用：产品交接、前端开发、后台开发、CMS 建模、测试验收

原型入口：`docs/prototype/wireframes/index.html`

本文件说明 V2.0 原型页面、页面结构、交互规则、组件拆分、CMS 字段、前后台映射和移动端适配。HTML 原型只作为信息架构与交互参考，不作为最终生产视觉代码。

## 1. 原型目标

本轮原型不是视觉草图，而是工程可继续开发的产品原型说明。目标是让工程师无需口头解释即可理解：

- 顶部导航和频道首页目标结构。
- 各前台页面应呈现哪些业务内容。
- 会员、认证、委员会、查询核验、用户中心的业务闭环。
- 每个栏目首页如何被 CMS 维护。
- 前台页面与后台 CMS、审核、RBAC、主数据之间的映射关系。
- 移动端和桌面端的布局规则。

## 2. 统一视觉方向

- 风格：东方极简、正式协会门户、米白纸感。
- 主色：深墨文字、米白背景、枣红重点、暖棕辅助。
- 禁止：冷蓝科技风、粗糙后台模板感、临时 Demo 感、单纯线框图。
- 页面应接近正式上线产品，但仍保留原型层面的可维护结构说明。
- 卡片、表单、表格和按钮应保持克制，避免过度阴影和过大圆角。

## 3. 顶部导航

所有前台原型统一使用以下导航：

1. 首页
2. 关于协会
3. 文化与道教
4. 会员服务
5. 认证服务
6. 发展中心
7. 交流合作
8. 数据中心
9. 查询核验
10. 用户中心

交互要求：

- 桌面端导航横向展示。
- 移动端单行横向滚动，不换行、不挤压。
- “关于协会”包含协会介绍、组织架构、规章制度、联系方式。
- “查询核验”聚合会员核验、机构会员核验、证书核验、申请进度查询。
- “用户中心”未登录进入登录 / 注册；登录后进入个人工作台。

## 5. 页面结构说明

### 5.1 首页

结构：

- Header：统一导航与登录入口。
- Hero：协会身份、门户定位、会员 / 认证 / 核验入口。
- 核心服务：会员服务、认证服务、查询核验、发展中心、委员会、交流合作、数据中心。
- V1.3 闭环：申请编号、后台审核、支付凭证、财务确认、证书 / 会员编号、公开核验、通知。
- 推荐内容：公告、制度更新、认证边界、数据公开边界。
- 底部 CTA：申请、查询、登录、联系。

交互：

- 主按钮进入会员申请、认证申请、查询核验。
- 推荐内容点击进入内容详情或栏目首页。
- 核验入口不提供 PDF 下载，只进入公开核验页面。

CMS：

- Banner、栏目简介、推荐内容区、公告模块、底部 CTA 均由 CMS 维护。

### 5.2 关于协会

结构：

- Hero：关于协会定位。
- 子栏目导航：协会介绍、规章制度、组织架构、联系方式。
- 协会介绍：宗旨、使命、服务对象、官网边界。
- 规章制度：章程、会员规则、认证建档规则、资料公开规则、申诉复核。
- 组织架构：理事会、秘书处、认证委员会、发展中心、委员会关系。
- 联系入口：会员申请、认证申请、合作联系、资料更正。

交互：

- 子栏目导航锚点跳转。
- 规章制度支持按分类筛选和查看生效版本。
- 联系入口进入对应业务流程。

CMS：

- 规章制度必须支持标题、副标题、正文、附件、版本号、生效日期、发布状态、SEO、是否推荐。

### 5.3 会员服务

结构：

- Hero：个人会员、机构会员、会员公开核验。
- 会员类型：个人会员、机构会员。
- 申请流程：提交资料、生成申请编号、后台审核、补充资料、支付凭证、财务确认、编号生成、公开核验。
- 材料说明：个人资料、机构资料、负责人资料、附件。
- 查询核验：会员编号 + 姓名 / 机构名称。

交互：

- 个人会员申请与机构会员申请分流。
- 上传支付凭证后进入财务审核，不自动变为已付款。
- 公众查询只展示核验结果和最小公开字段。

后台映射：

- `/admin/applications`：会员申请审核。
- `/admin/payments`：支付凭证和财务确认。
- `/admin/master-data`：引荐人、费用项目、会员类型。

### 5.4 认证服务

结构：

- Hero：认证服务定位和认证边界。
- 认证说明：道士认证申请、协会认证建档用途、非政府许可声明。
- 申请流程：材料提交、审核、补充资料、支付审核、复审 / 发证、PDF 下载、证书核验。
- 材料清单：身份证明、资历说明、照片、相关证明、授权确认。
- 查询核验：证书编号 + 持证人姓名。

交互：

- 未登录申请人进入登录 / 注册或申请记录绑定。
- 后台要求补件时用户中心显示补件任务。
- PDF 下载按钮只在登录且证书已签发时显示。
- 公众证书核验页不提供 PDF 下载。

后台映射：

- `/admin/certification-applications`：认证审核。
- `/admin/payments`：认证付款确认。
- `/admin/certificates`：证书生成、PDF、核验字段。

### 5.5 委员会业务

结构：

- Hero：委员会由需求方自行组建和筹办。
- 业务定位：向协会或发展中心申请，审核通过后自行运营。
- 流程：筹备、申请、初审、复审 / 批准、自行运营、发展中心监督、年度报告、任务缴纳、续期 / 整改 / 终止。
- 材料：委员会名称、宗旨、负责人、成员名单、运营计划、运营决议、年度报告、任务缴纳记录。
- 监督：发展中心代协会监督，记录风险和整改事项。

交互：

- 申请入口进入登录 / 注册或委员会申请表。
- 年度报告、运营决议、任务缴纳可作为用户中心待办。
- 后台可按状态筛选：待初审、复审中、已批准、运营中、需整改、暂停、终止。

后台映射：

- `/admin/committees`：委员会申请与运营管理。
- `/admin/development`：归口发展中心与监督记录。
- `/admin/payments`：任务 / 缴纳确认。
- `/admin/audit-logs`：监督和状态变更记录。

### 5.6 用户中心

结构：

- 登录 / 注册入口。
- 概览：申请状态、补件任务、待付款、已发证。
- 我的申请：个人会员、机构会员、认证申请、委员会申请。
- 我的会员：会员编号、状态、有效期、公开核验入口。
- 我的证书：证书编号、状态、PDF 下载、公开核验入口。
- 补充资料：按后台意见上传。
- 支付凭证：上传凭证、查看财务审核状态。
- 通知：申请、补件、付款、发证通知。

交互：

- 用户只能看到本人或本人机构授权记录。
- 补件上传后状态回到审核队列。
- PDF 下载前校验登录、归属、证书状态和文件权限。

### 5.7 后台管理首页

结构：

- 待办统计：会员待审核、认证待审核、支付待确认、委员会待处理、内容待发布。
- 模块入口：会员、认证、委员会、CMS、主数据、用户权限、审计日志。
- 风险提醒：Production、SQL、公开字段、权限变更、付款确认。

交互：

- 不同角色看到不同模块。
- 待办卡点击进入筛选后的列表。
- 高风险操作要求二次确认并写审计日志。

### 5.8 CMS 栏目首页维护

结构：

- 顶部频道列表：10 个顶部频道均可维护栏目首页。
- 页面模板：Banner、简介、推荐内容、子栏目导航、图文、公告、底部 CTA。
- 字段面板：标题、副标题、排序、发布状态、展示位置、SEO、封面图、正文、是否推荐。
- 审核发布：草稿、待审核、已发布、下架、归档、版本记录。

交互：

- 频道首页不是任意卡片堆叠，必须按模板区块维护。
- 重要频道发布前需要审核。
- 规章制度、认证、道医中医、易学、数据中心公开内容进入高风险审核。

### 5.9 RBAC 权限管理

结构：

- 用户：账号、组织、角色、状态、最近登录。
- 角色：超级管理员、协会管理员、内容管理员、会员审核员、认证审核员、财务审核员、委员会管理员、只读观察员。
- 权限：菜单权限、操作权限、审核权限、数据范围、敏感字段权限。
- 审计：权限变更记录、登录记录、导出记录。

交互：

- 角色变更需记录操作者和原因。
- 菜单不可见不等于接口无权限，后端 API 必须二次校验。
- 财务确认、发证、公开字段修改、权限变更等必须保留审计日志。

## 7. CMS 字段规则

每个频道首页至少维护：

- 栏目 Banner。
- 栏目简介。
- 推荐内容区。
- 子栏目导航。
- 图文模块。
- 公告模块。
- 底部 CTA。

后台字段：

| 字段 | 类型建议 | 说明 |
|---|---|---|
| 标题 | string | 页面 / 模块标题 |
| 副标题 | string | 页面 / 模块副标题 |
| 排序 | number | 模块、栏目、推荐内容排序 |
| 发布状态 | enum | draft / review / published / offline / archived |
| 展示位置 | enum | channel_home / home_featured / notice / cta / sub_nav |
| SEO 标题 | string | 页面 title |
| SEO 描述 | text | 页面 description |
| 封面图 | asset | 本地或媒体库图片 |
| 正文内容 | rich text / blocks | 结构化正文 |
| 是否推荐 | boolean | 是否进入推荐位 |
| 风险标记 | enum | normal / protected / sensitive |
| 版本记录 | relation | 发布版本、修改人、时间、说明 |

## 9. 移动端适配规则

- 页面最大宽度自适应，任何表格、编号、长英文、文件名不得造成横向溢出。
- Header 导航单行横向滚动。
- 主要 CTA 在移动端堆叠为纵向，按钮宽度 100%。
- 业务流程时间线在移动端改为单列。
- 后台表格在移动端允许横向滚动，但表格外层必须有明确滚动容器。
- 表单字段在移动端单列；上传、补件、付款凭证状态必须可完整阅读。
- 公共核验结果在移动端优先展示状态、编号、姓名 / 机构名称、有效期和人工复核入口。
- 证书 PDF 下载按钮仅在用户中心中出现，移动端需明确下载前权限状态。

## 10. 开发边界

- 本轮原型文件不连接数据库。
- 本轮不新增 SQL。
- 本轮不执行 SQL。
- 本轮不修改生产数据库。
- 本轮不发布 Production。
- 本轮不 push。
- 如后续发现现有页面、路由、数据库字段、接口与 PRD 不一致，应先在文档中列出差异，再进入独立开发任务。

## 11. 工程实现建议

1. 先将目标导航和现有路由做兼容映射，不直接删除旧路径。
2. 抽象 `ChannelHome` 模板，所有顶部频道使用相同数据结构渲染。
3. 将 CMS 字段先落成草案和静态 mock，再进入数据库 SQL 草案审批。
4. 将用户中心与公开查询区分：公开查询只核验，用户中心才下载 PDF。
5. 后台 RBAC 同时控制菜单、操作、审核节点、数据范围和敏感字段。
6. 委员会业务先做申请和后台管理闭环，再扩展运营报告、监督和任务缴纳细节。
7. 所有认证、道医中医、易学与东方认知、数据中心内容必须绑定边界说明区块。
