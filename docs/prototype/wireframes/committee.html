委员会业务

委员会由需求方自行组建和筹办，向协会或发展中心提交申请。审核通过后，委员会在批准范围内自行运营，由发展中心代协会进行监督。

发起委员会申请 查看流程 监督与报告
业务原则

协会提供申请、审核、监督和记录闭环，不替需求方直接运营委员会。

Position

业务定位

委员会业务应清晰区分“需求方自行筹办”和“协会 / 发展中心审核监督”的职责边界。

发起

需求方自行组建

需求方自行准备委员会名称、宗旨、负责人、成员名单和运营计划。

申请

提交协会或发展中心

选择归口发展中心或协会审核路径，提交申请材料和筹备说明。

运营

通过后自行运营

审核通过后，委员会按批准范围自行开展工作，保留活动和决议记录。

监督

发展中心代协会监督

发展中心记录年度报告、运营决议、任务缴纳、整改和风险事项。

Workflow

委员会业务流程

流程需同时在前台说明、用户中心待办和后台管理中体现。

1

筹备

需求方自行组建筹备小组，准备委员会名称、宗旨、负责人、成员和运营计划。

draft
2

申请

通过官网提交委员会申请，选择归口发展中心或协会审核路径，上传筹备材料。

submitted
3

初审与复审

后台检查资料完整性、业务方向、合规风险和负责人信息；通过后生成委员会档案。

reviewing
4

自行运营

委员会按批准范围自行开展工作，需保存运营决议、活动记录和成员变化。

active
5

监督与报告

发展中心代协会监督运营情况，委员会提交年度报告、运营决议并完成及缴纳相应任务。

supervised
6

续期 / 整改 / 终止

根据年度报告、任务缴纳和监督记录决定续期、整改、暂停或终止。

rectification

Application

委员会申请表结构

申请表应支持草稿、提交、补件、审核、批准和归档，不直接落为正式委员会。

基础信息

登录后发起申请

需提交材料

筹备成员名单

包含负责人、联系人、核心成员、职责分工和联系方式，后台按权限查看。

运营计划

说明年度目标、活动计划、资源安排、风险控制和资料归档方式。

运营决议

委员会成立、重大活动、成员调整、年度计划等决议文件需上传并归档。

年度报告

每年提交工作报告、任务完成说明、财务或缴纳情况、下一年度计划。

Supervision

发展中心监督与任务缴纳

委员会运营不等于放任运行。发展中心需要代协会记录监督、整改、年度报告和任务缴纳状态。

监督事项 委员会提交 后台处理 状态示例
运营决议 成立决议、活动决议、成员调整决议 委员会管理员审核并归档 已提交 / 需补充
年度报告 年度工作报告、活动总结、风险说明 发展中心审核并形成监督记录 待审核 / 已通过
任务完成 任务成果、资料沉淀、活动记录 关联发展中心项目和数据中心公开内容 进行中 / 已完成
任务缴纳 缴纳凭证或费用记录 财务确认，写入支付和审计日志 待缴纳 / 已确认
整改与终止 整改说明或终止申请 记录整改要求、期限、结果和处理意见 整改中 / 暂停 / 终止

Admin Mapping

后台管理映射

委员会业务需要新增后台模块或纳入发展中心后台，不应只作为前台说明页面。

委员会管理

申请与档案

处理申请、审核意见、归口中心、状态流转、负责人和成员信息。

发展中心管理

监督记录

发展中心代协会记录运营监督、风险提醒、整改要求和年度报告审核。

付款 / 审计

任务缴纳

委员会任务或缴纳事项进入付款管理，财务确认和状态变更写入审计日志。

委员会业务原型 · 需求方自行筹办 · 发展中心代协会监督 · 运营决议与年度报告必须归档。
