## 1. 项目定位

ITCA 官网 V2.0 不是单纯展示站，也不是只用于表单提交的临时工具站。最终产品应同时承担：

- 协会正式门户。
- 个人会员与机构会员服务入口。
- 道士认证及相关认证申请入口。
- 申请、审核、补充资料、支付凭证、财务确认、发证、公开核验业务闭环。
- 发展中心、交流合作、委员会业务和数据中心展示入口。
- 用户中心、自助进度查看、证书 PDF 下载和资料补充入口。
- SaaS 化后台管理、CMS、主数据、用户、角色、权限、审核、日志和通知配置。

V2.0 必须保留 V1.3 已形成的申请、审核、支付、证书、核验、通知、后台基础资料管理闭环，不得因门户升级破坏既有业务链路。

## 3. 产品范围与非范围

### 3.1 本期范围

- 前台官网：`首页`、`关于协会`、`文化与道教`、`会员服务`、`认证服务`、`发展中心`、`交流合作`、`数据中心`、`查询核验`、`用户中心`。
- 频道首页：每个顶部频道必须有独立栏目首页，并支持 CMS 维护。
- 会员业务：个人会员申请、机构会员申请、会员编号、后台审核、付款凭证、财务确认、会员公开查询核验。
- 认证业务：道士认证申请、材料提交、审核、补充资料、支付审核、发证、PDF 下载、公众证书核验。
- 委员会业务：需求方发起、自行组建筹办、向协会或发展中心申请、审核通过后自行运营、发展中心代协会监督、运营决议、年度报告、任务缴纳。
- 用户中心：登录 / 注册、我的申请、我的会员、我的证书、补充资料、支付凭证、PDF 下载。
- 后台：仪表盘、申请管理、会员管理、认证管理、委员会管理、CMS、数据中心、主数据、用户、角色、权限、审计日志、通知。
- SaaS 化基础：组织、角色、权限、用户、内容、主数据、审核、日志、模块配置和流程配置。

### 3.2 本期非范围

- 不自动执行 SQL。
- 不直接修改生产数据库。
- 不自动 push。
- 不自动发布 Production。
- 不删除 V1.3 既有业务代码、路由、数据结构和公开核验逻辑。
- 不把 Word / HTML 原型作为生产视觉代码直接复制；HTML 原型仅作为信息架构与交互参考。

## 7. 前台页面需求

### 7.1 首页

- 明确 ITCA 身份、协会定位和核心服务。
- 展示核心入口：关于协会、会员服务、认证服务、查询核验、发展中心、委员会、交流合作、数据中心。
- 保留 V1.3 业务入口：会员申请、认证申请、申请进度查询、支付凭证、证书核验、会员核验。
- 展示公告和重要边界说明。
- 视觉风格为东方极简、米白纸感、深墨文字、枣红 / 暖棕重点色，避免冷蓝科技风。

### 7.2 关于协会

- 合并协会介绍与规章制度。
- 内容包括协会宗旨、使命、定位、服务对象、组织架构、联系方式、章程制度、会员规则、认证建档规则、资料公开规则、申诉复核规则。
- 不夸大认证效力，不暗示法定资质替代。
- 规章制度支持 CMS 版本、发布日期、生效日期、修订说明和附件。

### 7.3 文化与道教

- 承接道教文化、信仰介绍、教理教义、文化资料、文章与活动内容。
- 内容定位为文化介绍和思想学习，不进入不适合公开传播的具体仪轨细节。
- 避免绝对化、神秘化、疗效化表达。

### 7.4 会员服务

- 展示个人会员、机构会员、会员权益、申请条件、申请入口、会员查询核验。
- 个人会员流程：提交资料、生成申请编号、后台审核、补充资料、上传支付凭证、财务确认、生成会员编号、公众查询核验。
- 机构会员流程：提交机构资料、负责人资料、资质材料、后台审核、支付审核、生成机构会员编号、公众查询核验。
- 会员身份不等同于资格认证。

### 7.5 认证服务

- 展示道士认证申请、认证说明、材料要求、申请流程、证书核验和申请进度查询。
- 流程：材料提交、审核、补充资料、支付审核、复审 / 发证、PDF 下载、公众证书核验。
- 证书 PDF 下载仅限申请人登录后下载；公众核验页只展示最小核验字段。

### 7.6 发展中心

- 说明发展中心是什么、服务对象、中心职责、项目合作、课程活动、资料沉淀和监督关系。
- 包含养生与修炼、文创产业、教育培训、国际与交流、易学与东方认知、道医中医研究等方向。
- 道医中医与易学东方认知必须有边界说明。

### 7.7 交流合作

- 面向文化机构、社团组织、研究单位、康养基地、课程团队、文创品牌、国际项目伙伴。
- 展示合作方向、合作流程、资料要求、联系入口和人工复核说明。
- 不提前承诺未确认项目，不将合作意向表述为协会背书。

### 7.8 数据中心

- 展示经审核允许公开的机构、个人、平台、传承、课程、产品、活动、基地等资料。
- 公开页面只展示经审核允许公开的信息。
- 不公开身份证件、联系方式、支付信息、申请材料、后台审核意见、内部备注和非公开附件。
- 支持纠错、撤回、隐藏、暂停展示和人工复核。

### 7.9 查询核验

- 聚合会员公众查询、机构会员公众查询、证书公众查询、申请进度查询。
- 查询核验只用于核验真实性和状态，不暴露敏感信息。
- 证书核验建议维持双字段校验：证书编号 + 持证人姓名。
- 会员核验建议维持最小字段校验：会员编号 + 姓名 / 机构名称。
- 证书 PDF 下载仅限申请人登录后在用户中心下载。

### 7.10 用户中心

- 未登录显示登录 / 注册。
- 登录后显示我的申请、我的会员、我的证书、补充资料、支付凭证、PDF 下载、通知、账号资料。
- 用户只能查看自己的申请、付款、证书、文件和通知。
- 历史申请可通过申请编号、姓名、手机号 / 邮箱等校验后绑定账号。

## 8. 会员、认证、支付、证书闭环

### 8.1 统一业务状态机

| 状态 | 名称 | 说明 |
|---|---|---|
| `draft` | 草稿 / 未提交 | 用户中心保存资料，未进入审核 |
| `submitted` | 已提交 | 生成申请编号，进入后台待初审 |
| `pre_review` | 初审中 | 审核员检查资料完整性和基础条件 |
| `needs_supplement` | 需补充资料 | 后台填写补充要求，用户上传补充材料 |
| `payment_pending` | 待付款 | 审核通过进入付款阶段，展示银行电汇信息 |
| `payment_submitted` | 已上传付款凭证 | 用户上传凭证，进入财务审核 |
| `payment_review` | 财务审核中 | 财务确认金额、账户、凭证真实性 |
| `paid` | 已确认付款 | 仅后台财务可确认，用户不能自行置为 paid |
| `final_review` | 复审中 | 业务复审 / 委员会复核 / 管理员确认 |
| `approved` | 已通过 | 生成会员编号或证书编号 |
| `rejected` | 已拒绝 | 记录拒绝原因，通知用户 |
| `issued` | 已发证 / 已生效 | 生成 PDF、公开核验可查、用户可下载授权文件 |
| `archived` | 已归档 | 业务结束或历史记录保留 |

### 8.2 支付审核规则

- 当前支付以银行电汇和后台人工审核为正式通道。
- 前台展示付款说明、银行信息、应付金额、申请编号和上传凭证入口。
- 用户上传付款凭证后进入 `payment_submitted` 或 `payment_review`。
- `paid` 状态必须由后台财务审核员确认。
- 财务审核不通过时需给出退回原因，用户可重新上传凭证。
- 财务确认、状态变更和导出必须写入审计日志。

### 8.3 证书与 PDF

- 证书编号由后台生成，不允许用户自行填写。
- 证书公开核验只返回必要公开字段。
- 证书详情页不得凭证书编号裸链访问敏感信息。
- PDF 下载只允许申请人登录后在用户中心下载。
- PDF 生成、下载、撤销、暂停、恢复等动作需保留操作记录。

### 8.4 通知触发

| 触发事件 | 接收对象 | 内容要求 |
|---|---|---|
| 提交成功 | 申请人 | 申请编号、查询入口、后续说明 |
| 需补充资料 | 申请人 | 补充资料清单、截止时间、上传入口 |
| 待付款 | 申请人 | 付款金额、银行信息、上传凭证入口 |
| 付款审核结果 | 申请人 / 财务 | 通过 / 退回原因、下一步操作 |
| 审核通过 / 拒绝 | 申请人 | 通过说明或拒绝原因 |
| 证书生成 / PDF 可下载 | 申请人 | 证书编号、下载入口、核验说明 |
| 后台待办提醒 | 审核员 / 财务 / 管理员 | 待处理申请、补充资料、付款凭证、复审事项 |

## 9. CMS 内容管理

### 9.1 CMS 后台能力

- 导航管理：频道名称、排序、路径、启用 / 隐藏、移动端显示策略。
- 频道首页管理：每个顶部频道拥有独立首页，可配置 Banner、简介、推荐内容、子栏目、图文模块、公告、底部 CTA。
- 内容页管理：文章、公告、规则、文化资料、发展中心内容、数据中心内容。
- 区块模板库：Hero、简介、流程、卡片、图文、时间线、FAQ、公告、数据指标、CTA、边界说明。
- 草稿 / 发布：编辑不直接影响线上，必须经过发布动作。
- 审核与版本：重要页面支持审核发布、版本记录和回滚。
- 风险标记：认证、规章制度、收费、道医中医、易学、数据公开等内容需加强审核。

| SEO 标题 | 页面 SEO title |

## 11. 委员会业务模块

### 11.1 业务定位

委员会业务不是由官网直接替协会强行设立委员会，而是提供申请、审核、运营记录、监督、年度报告和任务缴纳的管理闭环。

业务原则：

- 委员会由需求方自行组建和筹办。
- 需求方向协会或发展中心提交申请。
- 协会或发展中心审核通过后，委员会在批准范围内自行运营。
- 发展中心代协会监督委员会运营。
- 委员会需提交运营决议、年度报告，并完成及缴纳相应任务。

### 11.2 委员会流程

| 阶段 | 说明 |
|---|---|
| 筹备 | 需求方自行组建筹备小组，准备委员会名称、宗旨、负责人、成员、运营计划 |
| 申请 | 官网提交委员会申请，上传材料，选择归口发展中心 / 协会审核路径 |
| 初审 | 后台检查资料完整性、业务方向、合规风险、负责人信息 |
| 复审 / 批准 | 协会或发展中心审核通过后生成委员会档案和运营要求 |
| 自行运营 | 委员会按批准范围自行开展工作，保留运营决议和活动记录 |
| 监督 | 发展中心代表协会监督运营情况，记录整改、提醒、风险事项 |
| 年度报告 | 委员会提交年度工作报告、财务 / 任务完成说明 |
| 任务缴纳 | 完成并缴纳相应任务或费用，后台记录状态 |
| 续期 / 整改 / 终止 | 根据报告和监督情况决定续期、整改、暂停或终止 |

### 11.3 委员会字段建议

| 字段 | 说明 |
|---|---|
| `committee_name` | 委员会名称 |
| `committee_type` | 委员会类型 / 方向 |
| `sponsor_type` | 发起方类型：个人 / 机构 / 发展中心 / 其他 |
| `responsible_person` | 负责人姓名、联系方式、账号绑定 |
| `members` | 筹备成员 / 委员名单 |
| `development_center_id` | 归口发展中心 |

## 13. 边界说明

### 13.1 认证边界

认证内容用于协会内部审核、记录建档、证书签发、公开核验和文化交流参考。认证不应被表述为政府许可、法定职业资格、医疗资质、教育学历、宗教活动许可或任何可替代国家监管要求的资质。

### 13.2 道医中医边界

道医中医相关内容仅用于文化研究、养生知识、课程资料、合作展示和传统文化传播。不提供在线诊断，不替代执业医师诊疗建议，不承诺治疗效果，不鼓励用户停止、延误或替代正规医疗。

### 13.3 易学与东方认知边界

易学与东方认知相关内容仅用于传统文化学习、认知辅助、自我理解和文化产品体验。不作为医疗、法律、金融、投资、心理治疗、婚姻决策等专业建议，不作确定性预测承诺。

### 13.4 数据中心公开边界

数据中心公开展示遵守最小公开原则。只展示经审核允许公开的信息，不公开身份证件、联系方式、支付信息、申请材料、后台审核意见等敏感信息。
