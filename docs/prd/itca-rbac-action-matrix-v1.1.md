# ITCA RBAC 权限动作矩阵 v1.1

## SaaS 后台权限原则

- 后台一级模块包括：工作台、申请管理、审核中心、财务中心、会员中心、认证与证书中心、内容 CMS、发展中心管理、课程活动中心、合作中心、数据中心、通知中心、争议与风控、权限与组织、系统配置、审计日志。
- 所有列表支持筛选、搜索、排序，但导出必须单独授权并记录用途、范围、导出人、审批人和时间。
- 所有详情页包含顶部摘要、当前状态、下一步动作、关键字段、材料/附件、付款订单、审核记录、通知记录、公开授权、关联对象、操作时间线和审计记录；敏感区块按角色裁剪。
- 高风险动作必须二次确认并写入 `audit_logs`，财务相关事件同步写入 `payment_events`。
- CMS 权限不得修改申请表单字段校验、付款订单状态、证书 vt 访问规则、公开 DTO 字段范围、审核状态机流转、RBAC 权限逻辑、私有 Storage 文件路径或生产数据。
- 删除原则上改为归档、作废或隐藏，不做物理删除。

## 职责冲突规则

1. 初审和终审原则上不得同一人完成；例外需 Super Admin 审批并写入审计。
2. 财务审核和业务审核应分离；同一人不得同时确认付款并终审同一申请。
3. 证书撤销需要 Certificate Manager 或 Super Admin 权限、撤销原因、二次确认和审计。
4. 数据导出需要审批和审计，导出用途、范围、导出人、审批人、时间必须记录。
5. 批量操作必须记录，批量撤销、公开、导出需二次确认。
6. 管理员离职、停用或角色变更后必须立即回收权限并记录审计。
7. 删除原则上改为归档，不做物理删除；生产数据修改必须填写原因。
