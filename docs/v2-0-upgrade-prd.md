# ITCA 官网 V2.0 升级 PRD

## V2.0 总目标

ITCA 官网 V2.0 在 V1.3 已形成的申请、审核、支付、证书、核验、通知、后台基础资料管理业务闭环之上，升级为更完整的协会门户与业务承载平台。V2.0 的核心目标是固化导航升级版信息架构，补齐协会介绍、规章制度、道教信仰、教理教义、文化交流、发展中心、会员认证、证书查验、发展合作、数据中心、用户系统、后台 RBAC 权限体系等长期模块。

本轮仅做方案固化，不修改前台页面、后台页面、业务代码、SQL 或生产数据库。

## 顶部导航结构

顶部导航采用导航升级版信息架构，作为 V2.0 页面与频道规划依据：

- 首页
- 介绍
- 规章制度
- 道教信仰
- 教理教义
- 文化交流
- 发展中心
- 会员认证
- 证书查验
- 发展合作
- 数据中心

发展中心为一级导航下的重点下拉体系，包含六大发展中心：

- 养生与修炼发展中心
- 文创产业发展中心
- 教育培训发展中心
- 国际与交流发展中心
- 易学与东方认知发展中心
- 道医中医研究发展中心

## 首页结构

首页应作为 V2.0 总入口，保留 V1.3 的协会可信度、申请入口、证书核验入口和合作联系入口，同时增加 V2.0 的发展中心、会员认证、数据中心等入口。

建议首页结构：

- 首屏：协会名称、官方定位、核心行动入口。
- 核心服务入口：会员认证、证书查验、发展合作、数据中心。
- 协会介绍摘要：宗旨、使命、定位、国际合作。
- 发展中心摘要：六大发展中心入口。
- V1.3 业务入口：申请、审核进度查询、支付、证书、核验。
- 公告资讯：认证、会员、核验、合作等公开信息。
- 联系方式与重要说明。

首页视觉必须延续 V1.3，不照搬 HTML 原型中的深色视觉样式。

## 介绍页面

介绍页面用于展示协会基础身份与公共叙事，内容包括：

- 协会宗旨。
- 协会使命。
- 协会定位。
- 国际合作方向。
- 服务对象：会员、申请人、机构伙伴、文化交流对象。
- 与 V1.3 现有认证、会员、证书核验体系的关系。

介绍页面应保持稳健、克制、正式的协会表达，不夸大认证效力，不暗示法定资质替代。

## 规章制度页面

规章制度页面用于承载协会治理和业务规则的公开说明，内容包括：

- 协会章程与总则。
- 会员管理规则。
- 认证与建档规则。
- 资料使用规则。
- 证书签发与核验规则。
- 信息公开与隐私规则。
- 合作项目管理规则。
- 申诉、复核、暂停、撤销等状态说明。

该页面应与 V1.3 后台审核、材料补正、记录处置、证书有效期、核验安全等既有机制保持一致。

## 道教信仰页面

道教信仰页面用于面向公众介绍道教信仰文化，内容包括：

- 道法自然。
- 济世利人。
- 宫观文化。
- 神仙信仰。
- 斋醮仪式。
- 修行生活。
- 当代社会中的文化价值。

内容应作为文化介绍，不进入宗教活动承诺、功效承诺或不适合公开传播的具体仪轨细节。

## 教理教义页面

教理教义页面用于介绍道教经典思想、伦理观、修行观、生命观与当代表达，内容包括：

- 经典与思想导读。
- 道德经、南华经等基础内容入口。
- 伦理与修身。
- 生命与修炼。
- 基础术语解释。
- 学习路径与公开课程链接。

教理教义内容应避免绝对化、神秘化、疗效化表达，定位为文化学习与思想介绍。

## 文化交流页面

文化交流页面用于展示协会在国际交流、文化研究、课程研修、机构合作等方面的公共活动，内容包括：

- 国际交流。
- 文化研究。
- 课程研修。
- 机构合作。
- 会议、访问、展览、论坛等活动记录。
- 合作成果和公开资料。

该页面应与发展合作页面区分：文化交流偏内容展示和活动记录，发展合作偏合作入口和项目对接。

## 发展中心总览

发展中心总览是 V2.0 的核心频道，用于承接各类专委会、合作机构、课程项目、研究项目、认证项目和产业合作。

总览内容包括：

- 六大发展中心入口。
- 发展规划。
- 专委会体系。
- 项目合作。
- 活动发布。
- 课程与认证关联。
- 机构和专家协作入口。

发展中心总览应作为业务扩展的门户，不替代 V1.3 已有认证业务闭环。

## 六大发展中心

### 养生与修炼发展中心

围绕道家养生、功法修炼、辟谷、站桩、温泉养生、丹道等方向建立专委会、课程体系、活动体系与基地合作。

建议栏目：

- 站桩专委会。
- 温泉养生专委会。
- 辟谷专委会。
- 丹道专委会。
- 功法修炼专委会。
- 养生基地工作组。
- 生活道专委会。
- 安全与伦理工作组。

必须包含安全提示、适用人群、风险提示、非医疗承诺说明。

### 文创产业发展中心

围绕道教文化 IP、礼品、文创产品、联名项目、品牌会员与文化空间合作展开。

建议栏目：

- 文化 IP 与视觉体系。
- 高端礼品与联名。
- 文化空间合作。
- 文创产品库。
- 品牌会员合作。
- 授权与使用规则。

该中心应服务文化传播和产业合作，不改变协会认证业务的权威边界。

### 教育培训发展中心

承接道学院、基础课程、专业课程、研修营、师资培养、学习档案与结业认证。

建议栏目：

- 基础文化课程。
- 专业研修课程。
- 导师与师资。
- 证书与学习档案。
- 学员成长路径。
- 课程审核和反馈机制。

课程证书应与资格认证区分，避免将学习证明表达为职业许可或法定资质。

### 国际与交流发展中心

面向亚太、北美及更多区域，推动协会分支建设、国际合作、学术交流、会议活动与机构互认。

建议栏目：

- 地区协会协作。
- 国际项目合作。
- 会议与访问。
- 合作备忘录。
- 国际活动公告。
- 多语言资料入口。

国际合作内容应以公开合作事实和协会沟通结果为准，不提前承诺未确认项目。

### 易学与东方认知发展中心

围绕易学、河洛理数、六十四卦、五行能量、东方人格认知、人生结构理解等方向，建立现代化表达体系。

建议栏目：

- 易学研究。
- 东方人格认知。
- 工具与产品。
- 课程和学习档案。
- AI 辅助解读产品。
- 伦理与边界。

所有内容必须定位为文化参考、认知辅助和自我成长，不替代医疗、法律、金融、心理治疗等专业判断。

### 道医中医研究发展中心

围绕道医文化、中医养生、药膳、导引、身心调理等方向开展研究、课程、资料整理和合作展示。

建议栏目：

- 道医文化研究。
- 中医养生合作。
- 药膳与康养内容。
- 研究顾问机制。
- 内容审查机制。
- 合规与风险说明。

所有内容必须避免诊疗承诺、疗效保证和替代医疗建议。

## 会员认证页面

会员认证页面用于说明会员类型、加入路径、权益边界、学习成长、认证关联与活动参与方式。

建议会员类型：

- 注册用户：浏览公开内容、提交咨询。
- 基础会员：参与课程、活动、会员资讯。
- 认证会员：认证建档、证书核验、协会交流。
- 机构会员：机构展示、合作项目、活动共建。

会员认证页面必须与 V1.3 已有会员申请和认证申请闭环兼容，避免将会员身份等同于资格认证。

## 证书查验页面

证书查验页面保留 V1.3 的公开核验能力，并在 V2.0 中作为顶部导航核心入口。

功能边界：

- 支持证书编号、姓名或机构名称等必要条件查询。
- 展示证书状态：有效、待复核、暂停、撤销、未查询到记录等。
- 公开信息仅展示核验所需字段。
- 保留人工复核联系路径。
- 核验结果以官网查询页为准。

不得扩大公开字段范围，不得泄露申请材料和后台审核信息。

## 发展合作页面

发展合作页面面向文化机构、社团组织、研究单位、康养基地、课程团队、文创品牌与国际项目伙伴开放合作。

合作方向：

- 机构合作。
- 课程与活动合作。
- 产业与品牌合作。
- 国际交流合作。
- 数据中心入驻合作。
- 发展中心项目合作。

合作页面应提供明确的提交入口、材料要求、审核说明和后续联系机制。

## 数据中心页面

数据中心用于收录并展示道家与文化领域各分支的机构、个人、平台、传承、课程、活动、基地等资料，形成协会公开文化数据库。

建议库结构：

- 机构库。
- 个人库。
- 平台库。
- 传承库。
- 课程库。
- 产品库。
- 活动库。
- 基地库。

数据中心应采用公开展示与后台审核分离机制。公开页面只展示经审核允许公开的信息，后台保留审核、隐藏、撤回、纠错、记录处置等管理能力。

## 用户系统

V2.0 后续目标包含用户系统，用于承接注册用户、会员、认证申请人、机构账号、合作伙伴等身份。

用户系统建议能力：

- 注册、登录、退出。
- 账号资料管理。
- 手机或邮箱绑定。
- 申请记录关联。
- 支付记录关联。
- 证书记录关联。
- 会员身份状态。
- 机构账号和联系人管理。
- 通知接收和站内消息。

用户系统必须兼容 V1.3 现有申请查询、支付、证书和后台审核流程。涉及数据库结构时只能先新增 SQL 草案文件，不得直接执行。

## 后台管理员权限体系 / RBAC

V2.0 后续目标包含后台管理员权限体系 / RBAC，用于将后台操作从单一管理员能力升级为角色化、权限化、可审计的管理体系。

建议角色：

- 超级管理员。
- 业务审核员。
- 财务管理员。
- 证书管理员。
- 会员管理员。
- 内容管理员。
- 数据中心管理员。
- 只读审计员。

建议权限域：

- 申请审核。
- 材料补正。
- 支付管理。
- 证书签发和撤销。
- 核验信息管理。
- 会员管理。
- 课程和活动管理。
- 数据中心资料审核。
- 内容发布。
- 后台基础资料管理。
- 审计日志查看。

RBAC 必须保留 V1.3 后台基础资料管理和审计思路。涉及表结构、策略或迁移时只能新增 SQL 草案文件，不得执行 SQL。

## 认证边界说明

认证内容用于协会内部审核、记录建档、证书签发、公开核验和文化交流参考。认证不应被表述为政府许可、法定职业资格、医疗资质、教育学历、宗教活动许可或任何可替代国家监管要求的资质。

所有认证页面必须明确：

- 认证结果以协会官网公开核验为准。
- 认证材料用于审核、建档和后续服务。
- 证书状态可能因复核、暂停、撤销等情况变化。
- 申请人应对提交材料真实性负责。

## 道医中医边界说明

道医中医相关内容仅用于文化研究、养生知识、课程资料、合作展示和传统文化传播。

必须明确：

- 不提供在线诊断。
- 不替代执业医师诊疗建议。
- 不承诺治疗效果。
- 不鼓励用户停止、延误或替代正规医疗。
- 涉及健康风险、禁忌、适用人群时必须加入风险提示。

## 易学与东方认知边界说明

易学与东方认知相关内容仅用于传统文化学习、认知辅助、自我理解和文化产品体验。

必须明确：

- 不作为医疗、法律、金融、投资、心理治疗、婚姻决策等专业建议。
- 不作确定性预测承诺。
- 不鼓励用户以单一解读替代现实判断。
- 工具或 AI 解读结果只作为文化参考。

## 数据中心公开信息边界说明

数据中心公开展示必须遵守最小公开原则。

公开信息边界：

- 只展示经审核允许公开的信息。
- 不公开身份证件、联系方式、支付信息、申请材料、后台审核意见等敏感信息。
- 支持纠错、撤回、隐藏、暂停展示。
- 证书、会员、机构等状态应与后台审核记录保持一致。
- 公开数据不得被表述为政府背书或法定名录。

## 视觉延续 V1.3 的要求

V2.0 视觉必须延续 V1.3 已有网站气质和组件基础：

- 延续现有品牌、字体、色彩、留白、按钮、卡片、页眉、页脚和内容密度。
- 不做视觉系统重构。
- 不照搬 HTML 原型中的深色视觉样式。
- 不引入与 V1.3 明显冲突的新视觉语言。
- 新页面应优先复用现有组件和布局模式。

HTML 原型仅作为导航结构、栏目结构和内容结构参考。

## V1.3 业务闭环保留要求

V2.0 必须保留并兼容 V1.3 已完成或规划中的业务闭环：

- 申请提交。
- 后台审核。
- 材料补正。
- 支付与支付记录。
- 证书签发。
- 证书 PDF 或证书资料。
- 公开核验。
- 通知发送。
- 后台基础资料管理。
- 审计日志和记录处置思路。

任何 V2.0 页面、用户系统或 RBAC 设计不得破坏上述业务链路。
