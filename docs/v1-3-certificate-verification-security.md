# V1.3 证书核验安全机制

## 目标

V1.3 第 2 阶段保留证书详情页，但禁止公众通过证书编号裸链直接访问详情。公众必须先在 `/certificate-query` 输入证书编号与持证人姓名，核验成功后获得短期核验凭证 `vt`，再访问 `/certificates/[certificateNo]?vt=xxx` 查看公开证书详情。

## 核验流程

1. 公众访问 `/certificate-query`。
2. 输入证书编号与持证人姓名。
3. 前端调用 .NET API `/api/certificates/query`。
4. .NET API 确认证书编号、持证人姓名、公开查询开关和证书状态均匹配。
5. 查询成功后，API 返回公开证书字段、`verificationToken` 和可跳转的 `detailUrl`。
6. 前端显示当前公开查询结果，并提供“查看证书核验详情”按钮。
7. 用户访问 `/certificates/[certificateNo]?vt=xxx`。
8. 详情页调用 .NET API `/api/certificates/{certificateNo}?vt=xxx`。
9. .NET API 校验 `vt` 有效、未过期，且绑定的证书编号与路径中的 `certificateNo` 一致后，才返回公开证书详情。

## 为什么不能证书编号裸链直达

证书编号可能被转发、截图、收录或猜测。若详情页仅依赖证书编号展示信息，第三方可以绕过“证书编号 + 持证人姓名”的核验步骤直接访问公开详情。V1.3 将详情访问改为短期核验链接，降低证书编号裸露后的直接访问风险。

## vt 的作用

`vt` 是服务端签名的短期核验凭证：

- 由 .NET API 在证书编号与持证人姓名核验成功后生成。
- 绑定证书编号。
- 不包含联系方式、证件、材料路径、审核备注等隐私字段。
- 不需要新增数据库表。
- 详情 API 必须先校验 `vt`，再返回公开证书详情。

## vt 有效期

当前有效期为 15 分钟。过期后，详情页不展示证书详情，用户需返回 `/certificate-query` 重新输入证书编号与持证人姓名完成核验。

## 允许公开字段

- 证书编号
- 持证人姓名
- 认证类型
- 认证路径 / 等级
- 签发机构
- 签发日期
- 有效期
- 证书状态
- 核验说明

## 禁止公开字段

- application_id
- 申请编号
- 联系方式
- 邮箱
- 手机
- 地址
- 身份证件
- 推荐信
- 无犯罪证明
- 上传材料路径
- Supabase Storage path
- 内部审核备注
- 对申请人的补充反馈
- 后台操作记录
- 管理员信息

## 后续二维码 / PDF 防伪衔接

后续若增加二维码或 PDF 证书，二维码不应直接使用证书编号裸链。建议二维码进入 `/certificate-query` 或进入带短期 / 一次性核验凭证的详情链接。PDF 防伪也应复用同一套“先核验、再短期授权查看详情”的规则，避免 PDF 上的证书编号成为长期公开详情入口。

## 生产环境变量

生产环境需要配置：

- `ITCA_VERIFICATION_TOKEN_SECRET`

该变量用于签名和校验证书核验 `vt`。不要将密钥写入代码、文档或仓库。若本地开发未配置该变量，API 会使用进程内随机 fallback；该 fallback 仅适合本地开发，服务重启后已生成的本地 `vt` 会失效。
